# Security Policy

## Reporting a vulnerability

Do **not** post exploit details, private user information, passwords, tokens, keys, or unpublished security findings in public issues or discussions.

If GitHub **Private vulnerability reporting** is enabled, use the repository **Security** tab to report concerns confidentially. If it is not enabled, contact the repository maintainer using an established private channel. Public GitHub issues are not private.

This repository includes an upstream third-party project. Report vulnerabilities in upstream code to that project's maintainers; this repository's maintainer is responsible only for its own changes. Preserve all upstream copyright notices and license requirements.

## Safeguards

- Keep production keys, credentials, tokens, and customer data out of Git.
- Rotate potentially exposed credentials and use protected deployment secrets.
- Review dependencies, licenses, and privacy impacts before publishing.
- Enable branch protection, dependency scanning, and secret alerts when supported.
- Maintain independent backups and periodically verify restoration.

These are policy requirements, not proof that every feature is configured or that the code has been independently audited.

## Rights

This policy does not alter existing licenses, assign copyright, or establish intellectual property ownership. Third-party and upstream rights remain with their respective owners.
